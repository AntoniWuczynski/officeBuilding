Every request carries `store` false, asks for no reasoning summary and names no earlier response. `max_tokens` goes as `max_output_tokens`, and a value from 1 to 15 is sent as 16, OpenAI's documented minimum. A failed tool result gets one added first line, because OpenAI's tool output has no error flag (OB-275).
  - **Effort:** the effort sent is the one in force for the reply by Anthropic's rule for an effort on a message entry, mapped by the connection's own pairs for the request's tier. An effort in force that has no pair refuses the request. This is the part of OB-239 that was left to this stage, with two gaps (OB-271, OB-280).
  - **The reply** (`translate/sse.rs`, `translate/reply.rs`): OpenAI's stream events become Anthropic's. Text and the model's own refusal text become text blocks, a function call becomes a tool call that keeps OpenAI's identifier, and a reasoning item leaves no trace. The reply's identifier and model name are OpenAI's own. Cached and written input tokens are reported under Anthropic's names (OB-272). An event type the reader does not know is ignored, and an output item it cannot carry fails the reply.
  - **The commit boundary** (`translate/pump.rs`, `router/relay/translated.rs`): nothing is written to the client, not even the reply's head, before the first translated bytes. Those are the first text that is not empty, a function call or the event that ends the reply. A failure before them is answered with a true status, and it can still be retried once or move the desk, by the first stage's rules. A failure after them gives the client one `error` event and a stream cut short without its terminator. That request is never sent again, the desk is not moved for it, and the reply never ends with `message_stop`. A used-up code that arrives after the first bytes is recorded, so the next request moves the desk.
  - **Evidence** (`evidence.rs`): a used-up OpenAI allowance is proven only by an HTTP 429 with one of four documented codes, or by an `error` event in the stream with one of them. A status alone never proves it, and neither does `response.failed` (OB-276). A documented throttle is a throttle, and a code with no row is shown to the desk and moves nothing. OpenAI's own message is shown only for a rejected or forbidden request, on one line of at most 300 characters, and it is never stored or logged.
  - **What reaches OpenAI** (`upstream.rs`): the request goes to OpenAI's own API host and nowhere else, with four headers the router writes itself. No header the client sent and no query string crosses, so the desk's Claude login, the route secret and every `anthropic-*` and `x-claude-code-*` header cannot reach OpenAI on any path. The key is read from the Keychain for the one call and sent as a bearer token to that host only. A refusal from OpenAI is put into Anthropic's envelope by the router, so OpenAI's own bytes never reach the client.
  - **A translated route can carry images** (`capabilities.rs`). A desk that has sent an image can therefore be moved to an OpenAI connection, and one that has used a document or a tool the provider runs cannot (OB-265).
  - **The interface:** only sentences changed. The OpenAI API key card says what the route carries, leaves out and refuses, and that it has never been run against a real OpenAI account. The route strip's Details say that hidden reasoning is left out of every request sent to OpenAI. The picker and a hand-edited Sign in with ChatGPT card say that it is not built and what is missing. There is no new app call, wire type, event or snapshot field.
  - **The compatibility matrix:** `docs/provider-routing-matrix.md`, linked from the README. It lists every pairing of frontend and connection as checked by a live probe, built and not checked, experimental and not checked, or unavailable, with the reason. One pairing has carried a real request, Claude Code on a Claude subscription.
