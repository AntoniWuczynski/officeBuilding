  - **How its tools reach the app:** Claude Code starts a helper, which is the app's own binary run as `office-building manager-mcp <socket>`. A branch at the top of `main.rs` serves that mode and never starts the window. The helper passes the manager's MCP messages to a Unix socket the running app listens on, at `ipc/m.sock` in the app's data folder. Nothing listens on a network port.
  - **The socket:** its folder is made with mode 0700 before the socket is bound, and the socket file is then set to 0600. A folder that is a symbolic link is refused, and so is anything at the socket's path that is not a socket. A socket that a live listener still answers is left alone. A path over 100 bytes is refused, and a hire then says why. The app serves at most 8 connections. A connection has 5 seconds to send a first line of at most 256 bytes, and every later line is at most 65,536 bytes.
  - **The token:** 32 bytes from macOS's own random source, one for each launch of a manager, kept in memory only. It reaches the manager through the environment of its terminal's process (`OFFICE_BUILDING_MANAGER_TOKEN`). It is not in the command string, the generated `mcp.json`, `settings.json`, `store.json`, the snapshot, the log or any error message. The app compares it in constant time with every registered token. A wrong token gets a bare refusal after 300 ms. The token is revoked when the manager's terminal exits, and hiring again on a floor replaces it.
  - **Floor binding:** a connection is tied to one floor when it authenticates, and no tool takes a floor as an argument. A desk on another floor and a desk that does not exist get the same answer. The manager's own session, the QA reviewer and plain shells are not desks.

The limits are 4,000 characters a note, 2,000 a task, 5 waiting notes a desk and 20 a floor, 200 lines and 8,000 characters a read, and 6 options and 10 open calls for escalations.
